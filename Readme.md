# Simple WPI (Windows Post-Install)
[![GitHub All Releases](https://shields.io)](https://github.com)

Simple WPI is a lightweight and flexible automatic software installer for Windows operating systems. It is designed to deploy the entire required software package in **"silent mode"** (without user intervention), automatically adapting to the OS architecture and intelligently checking for already installed application versions. The program requires no installation and is perfect for running from a USB flash drive or within a WinPE environment.

---

## 🚀 Key Features

* **"Silent" installation:** Complete automation of the software installation process without extra clicks, dialog boxes, or confirmations.
* **Optional run as administrator:** This function can be configured in the program settings. When enabled, Simple WPI requests elevated privileges (UAC), ensuring that the installed applications have sufficient rights to write to system folders and the registry.
* **Automatic architecture selection:** The program independently selects the required architecture for the installers (x86 or x64) depending on the OS architecture.
* **Child process control:** Ability to enable the "Wait for all processes to complete" option. The installer will monitor not only the launched file itself but also all processes generated by it, moving to the next program only after they are completely closed (**USE WITH CAUTION!!!**).
* **Convenient management (Drag and Drop):** Support for quick dragging of installer files directly from Windows Explorer into the program window for instant addition.
* **Moving software between categories:** Ability to drag programs with the mouse for their quick distribution into the required categories.
* **Fast sorting of categories and programs:** Changing the order of the categories themselves, as well as items inside the lists on the fly using the held `Ctrl` key and mouse wheel scrolling.
* **Flexible launch modes:** Support for a completely hidden background installation or launching with a compact progress bar displayed via the command line.
* **Smart software detection:** The program can recognize software already installed in the system by file/folder paths, registry keys, unique GUIDs, or the application's display name.
* **Intelligent version control:** When scanning paths, Simple WPI compares the version of the installed application with the version of the installer, clearly highlighting the status in the list.
* **Installation profiles:** Ability to create ready-made software lists (scripts) for different tasks and instantly load them.
* **Environment variables support:** Correctly handles Windows system variables (such as `%AppData%`, `%ProgramFiles%`, `%SystemRoot%`, etc.) in paths.
* **Full customization:** Support for individual icon replacement for programs and categories (from `.ico`, `.exe`, `.dll` files), changing fonts, titles, as well as choosing a sound notification upon completion.

## 🛠 Detailed Functionality and Operation Logic

<details>
<summary><b>1. Automatic Architecture Selection (x86 / x64)</b></summary>

Simple WPI independently determines the architecture of the current operating system and selects the corresponding installer file for it. For this feature to work correctly, program files must be renamed according to one of the following supported templates:

* **Separated by an underscore:**
  `file_x86.exe` / `file_x64.exe` or `setup_x86.msi` / `setup_x64.msi`
* **Separate with a minus sign:**
  `file-x86.exe` / `file-x64.exe` or `setup-x86.msi` / `setup-x64.msi`
* **Continuous architecture writing:**
  `filex86.exe` / `filex64.exe` or `setup32.msi` / `setup64.msi`
* **Universal name (as x86) + x64 pair:**
  `file.exe` (perceived as x86) / `file_x64.exe` or `setup.msi` / `setup64.msi`
* **Complex compound names:**
  `my_cool_app_v2.1_x86.exe` / `my_cool_app_v2.1_x64.exe`

> ⚠️ **Important exception:** If there is only one single executable file with such a name in the program folder, the installer will launch and install it anyway, regardless of its name and system architecture.
</details>
<details>
<summary><b>2. Methods for Detecting Installed Programs and Color Coding</b></summary>

The installer checks whether the application is present on the user's computer in four independent ways: by file/folder path, by registry key, by GUID, or by display name. 

Depending on the program's state, rows in the list are dynamically colored in different colors:
* 🟢 **GREEN color** — The program is already installed in the system (current or newer version).
* 🟡 **YELLOW color** — The program is installed, but an older version is detected (update required). If a specific path to a concrete executable (`.exe`) file or an installation package (`.msi`) is specified in the search criteria, Simple WPI automatically extracts its version and compares it with the version of the software being installed. If the installed version is lower, the row will turn yellow.
* ⚪ **Grey color** — The program is incompatible with the current system (for example, x64 architecture on 32-bit Windows).
* 🔵 **BLUE color** — The program is currently installing (active process).
* 🔴 **RED color** — Program installation ended with an error.

### Technical search criteria for configuration:
* **By file or folder path:**
  If the specified object physically exists on the disk, the program is considered installed. 
  *\* Important:* The feature for automatic version extraction and comparison works exclusively when specifying the path to a concrete executable file of the `.exe` format or an installation package of the `.msi` format. If a folder path is specified, the installer checks only the fact of its existence.
* **By registry key:**
  If the specified key exists, the program is considered installed. The path to the key must begin with the standard name of the root section (both full names and common abbreviations are supported):
  `HKEY_LOCAL_MACHINE` or `HKLM`, `HKEY_CURRENT_USER` or `HKCU`, `HKEY_CLASSES_ROOT` or `HKCR`.
* **By GUID (product identifier):**
  Simple WPI automatically searches for the program in the Windows system uninstallation sections (Uninstall). The search algorithm is case-insensitive and resilient to the input format:
  `{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}` (with brackets) or `F3017226-FE2A-4295-8BDF-00C3A9A7E4C5` (without brackets).
* **By display name:**
  It is enough to specify the text name of the application or a part of it. Case insensitive. Examples: `WinRAR archiver`, `WinRAR` (partial match), `7-Zip`, `Google Chrome`.
</details>

<details>
<summary><b>3. Interactive Management and Sorting (Drag and Drop)</b></summary>

The Simple WPI interface is designed to minimize manual work with text configuration files as much as possible. Populating and organizing the program database occurs visually and interactively directly in the main window:
* **Adding programs from Explorer:** You can simply select the required installer files in the Windows folder and drag them with the mouse (Drag and Drop) directly into the Simple WPI interface.
* **Moving programs between categories:** To move a program from one category to another, simply hold it with the left mouse button and drag it to the desired category.
* **Smart sorting of categories and programs (Ctrl + Wheel):** To quickly change the order of programs inside a list or swap entire categories, hover over the element, hold down the `Ctrl` key on the keyboard, and scroll the mouse wheel up or down.
</details>

<details>
<summary><b>4. Silent Installation and Command Line (CLI Mode)</b></summary>

You can run the program installation process in fully automatic mode without displaying the main interface. To do this, first select the required software with checkboxes in the GUI, save it to an installation list file (`.lst`), and then run Simple WPI via the command line using the following switches:
* `/s` — completely silent mode (the installer window is not displayed at all).
* `"path_to_file.lst"` — path to the saved installation list (EXCLUSIVELY relative path in quotes).
* `/p` — displaying a compact window with a progress bar, the name of the application currently being installed, and a "Cancel" button.

### Examples of a startup command:
```cmd
SimpleWPI.exe /s "InstallList\my_install_list.lst" /p
SimpleWPI.exe /s "my_install_list.lst" /p
```

> ⚠️ **Important note on child processes (USE WITH CAUTION!!!):** The option *"Wait for all processes to complete"* should be used with great caution. Enable it only for those installers that really require it (complex repacks or SFX archives that launch third-party child packages and instantly close themselves). 
> 
> **Why this is critical:** Some modern programs (browsers, launchers, antiviruses) immediately during or upon completion of their installation launch permanent background services, system tray agents, or automatic update modules (for example, Google Update, Steam Client Service, background processes of messengers). Since these background processes remain running in the system, Simple WPI will infinitely wait for them to close. As a result, the entire installation queue will hang on this program. For most standard and simple installers, it is recommended to leave this option turned off.
</details>

<details>
<summary><b>5. Appearance Customization (Rebranding)</b></summary>

* **Window title:** Changing the displayed program name at the very top of the main window.
* **Custom icon:** Place an `.ico` file named EXACTLY THE SAME as the executable file next to the installer.
* **Welcome screen (Splash Screen):** Place a PNG format file (must have transparency!) named exactly like the executable file next to the installer.
* **Completion sound:** You can set your own sound signal for the end of installation in `.wav`, `ogg`, `flac` format (PCM codec recommended for `.wav`).
</details>

<details>
<summary><b>6. Executable File Renaming Rules</b></summary>

You can rename the main program file however you like. However, the 32-bit version **MUST** have the same name, but with the `_x86` suffix.

### Example of a correct file structure when renaming:
* `SuperInstall.exe` — Main executable file (64-bit).
* `SuperInstall_x86.exe` — Executable file for 32-bit systems (mandatory name!).
* `SuperInstall.ini` — Program settings file.
* `SuperInstall.db` — Icon cache database file.
* `SuperInstall.ico` — Custom application icon.
* `SuperInstall.png` — Custom splash screen (must have transparency).
</details>
